# SuperSkinPro — Code Size Reduction Execution Brief

## Context for the executing agent

This is a Blender addon (Python + Rust hybrid) with a strict 3-layer
architecture (`core/` → `core_subsystems/` → `features/`, fronted by
`interface/`). The goal of this task is to reduce overall source size by
removing dead/deprecated code and consolidating duplicated logic — **without**
changing any `CoreFacade` public method signature, any `bl_idname` /
`bl_label` / operator class name, or any Rust FFI string (`rust_*`).

Read `CLAUDE.md` at the project root before starting. Follow the
README-First Rule: read the local `README.md` of any package you touch
before editing files inside it.

This brief is organized into **Phases**. Phases are ordered by risk, from
safest (delete verified-dead code) to riskiest (behavior migration that
touches operators end-users click every day). **Execute phases in order.**
Do not skip ahead to a later phase before the previous one is verified
working (Blender loads with no console errors, F3 > Reload Scripts works,
and the manual smoke-test steps listed under each phase pass).

After every phase: run a search across the whole repository for any leftover
references to symbols you deleted, before moving to the next phase.

## PHASE 1A — Delete fully-shadowed dead prefs files

**Risk: none. Proven by direct code-overwrite logic, not inference.**

`PrefsExtensionRegistry.register()` de-duplicates by `json_key`: registering
a second spec with the same `json_key` silently replaces the first. In both
`deform_bone_viewer` and `layer_viewer`, `prefs.register()` runs first and
registers `json_key="deform_bone_viewer"` / `"layer_viewer"`, and then
`*_feature.register()`'s internal `_register_legacy()` immediately
re-registers a spec with the **same `json_key`**, overwriting it. This makes
every line of `prefs.py` in both packages permanently unreachable from the
moment registration finishes.

### Files to delete
- `features/deform_bone_viewer/prefs.py`
- `features/layer_viewer/prefs.py`

### Files to edit

**`features/deform_bone_viewer/__init__.py`**
- Remove `from . import prefs`
- Remove `prefs` from the `for mod in (...)` reload tuple
- Remove `prefs.register()` from `register()`
- Remove `prefs.unregister()` from `unregister()`

**`features/layer_viewer/__init__.py`**
- Same four edits, targeting `layer_viewer`'s `prefs` import.

### Verification
- Blender loads with no `ModuleNotFoundError` / `AttributeError`.
- F3 > Reload Scripts succeeds with no traceback.
- The Deform Bones list still renders under SKINNING tab in Edit Mode.
- The Layers list still renders under LAYER tab in Object Mode.
- "Save Weight and Exit" and "Edit Layer Weight" buttons still work.

## PHASE 1B — Remove the dead half of the legacy dual-registration shim

**Risk: low. `PrefsExtensionSpec` draw/populate/serialize paths are proven
dead; `DomainRegistry` action-dispatch paths are proven live and must NOT
be touched in this phase.**

### Background
Every `*_feature.py` file (12 total, listed below) contains a
`_register_legacy()` function that does two unrelated things:
1. Registers a `BaseDomain` subclass with `DomainRegistry` — **this is
   still live**, because `interface/utils/op_exec.py`'s `run_domain()`
   dispatches through `DomainRegistry.execute()`, and multiple operators
   still call `run_domain()` (see Phase 0, item 2).
2. Registers a `PrefsExtensionSpec` with `PrefsExtensionRegistry` — **this
   is dead for UI drawing** (confirmed in Phase 0, item 3:
   `widget_preferences.py` never reads from `PrefsExtensionRegistry`), but
   its `populate_fn`/`serialize_into_fn` **are** still invoked by
   `PreferencesService.load()` / `.save_to_user_file()` / `.reset_to_default()`,
   duplicating work that `UnifiedFeatureExtension.populate()` /
   `.serialize_into()` already does on the same object, writing the exact
   same values twice per call. This is pure redundant work, safe to delete.

Only remove part (2). Part (1) — the `DomainRegistry.register(_XDomain())`
call and its containing `class _XDomain(BaseDomain): ...` — must remain
untouched until Phase 2.

### Files to edit — remove ONLY the `PrefsExtensionSpec` registration block

In each of the 12 files below, inside `_register_legacy()`, delete the
`PrefsExtensionRegistry.register(PrefsExtensionSpec(...))` call (the whole
statement, including its keyword arguments) and, if now unused in that
scope, remove the now-dangling `PrefsExtensionRegistry, PrefsExtensionSpec`
names from the `from ...interface.registry import DomainRegistry, BaseDomain, PrefsExtensionRegistry, PrefsExtensionSpec`
line — keep `DomainRegistry, BaseDomain` imported since part (1) still
needs them.

Also delete the matching `_unregister_legacy()` body
(`PrefsExtensionRegistry.unregister("...")` call) in each file, since there
is no longer a spec registered to unregister. Leave `_unregister_legacy()`
as an empty function only if nothing else in that function's `try` block
remains meaningful — otherwise leave the rest of `_unregister_legacy()` as
it is; only remove the `PrefsExtensionRegistry.unregister(...)` line.

Files (all under `features/`):

3. `circle_tool_adjust/circle_tool_adjust_feature.py`

6. `data_io/data_io_feature.py`
7. `deform_bone_viewer/deform_bone_viewer_feature.py`

## PHASE 4 — Consolidate `core/facade` cache duplication with `TopologyCacheManager`

**Risk: low. Does not change any public `CoreFacade` method signature.**

`core/facade/__init__.py`'s `CoreFacade` class defines its own
`_mapping_cache` / `_neighbor_cache` class dicts and `_local_mapping()` /
`_cached_mesh_neighbors()` methods, computing the exact same values as
`core_subsystems/topology_cache_manager/topology_cache_manager.py`'s
`TopologyCacheManager.get_local_mapping()` / `.get_cached_mesh_neighbors()`
— which `core/facade/read.py`'s `ReadFacadeMixin.get_local_mapping()` /
`.get_cached_mesh_neighbors()` already correctly delegate to. This means
two independent, out-of-sync caches exist for the same data.

- In `core/facade/__init__.py`:
  - Delete the `_mapping_cache`, `_neighbor_cache` class attributes.
  - Delete the `_local_mapping()` and `_cached_mesh_neighbors()` methods.
  - Find every internal call site within `core/` that calls
    `self._local_mapping()` or `self._cached_mesh_neighbors()` directly
    (rather than the public `get_local_mapping()` / `get_cached_mesh_neighbors()`
    facade methods) and redirect them to call
    `TopologyCacheManager.get_local_mapping(self.obj, self.storage)` /
    `TopologyCacheManager.get_cached_mesh_neighbors(self.mesh, self.storage)`
    directly (same call the mixin already makes), or to the public facade
    methods if a `CoreFacade` instance is already in scope at the call
    site.

### Verification

  (weight apply, smooth, sharpen, mirror, auto-block) still produces

## PHASE 7 — Consolidate Clipboard manual vs automatic pipelines

**Risk: medium. Behavioral logic consolidation inside `features/clipboard/logic.py` —
requires careful equivalence checking since this is user-facing data
manipulation (copy/cut/paste of weight data).**

`features/clipboard/logic.py` contains two near-duplicate pipelines:
`copy()`/`cut()`/`paste()` (context-driven, reads `ctrl._is_mask_context()`)
and `copy_data_manual()`/`paste_data_manual()` (enum-driven, reads
`prefs.target_data_type`). The internal control flow (whole-mesh fallback
check, subset extraction, bone-compatibility validation, target
resolution, merge) is identical between the two; only the source of the
`is_mask` boolean differs.

- Extract a shared private function, e.g.
  `_copy_impl(ctrl, is_mask: bool) -> dict`, containing the body currently
  duplicated between `copy()` and `copy_data_manual()`'s non-cut branch.
- Extract a shared private function, e.g.
  `_paste_impl(ctrl, is_mask_target: bool, mode: str) -> dict`, containing
  the body duplicated between `paste()` and `paste_data_manual()`.
- Rewrite `copy(ctrl)` to call `_copy_impl(ctrl, ctrl._is_mask_context())`.
- Rewrite `copy_data_manual(ctrl, action='COPY')` to call
  `_copy_impl(ctrl, prefs.target_data_type == 'LAYER')`, preserving its
  existing `action='CUT'` branch logic (which should also be extracted into
  a shared `_cut_impl` if it matches `cut()`'s body closely — verify this
  by diffing the two bodies carefully first, since `cut()` calls `copy()`
  internally while `copy_data_manual(action='CUT')` inlines the clear-source
  step; make sure the extraction preserves exact existing behavior for both
  paths).
- Rewrite `paste(ctrl, mode='REPLACE')` and `paste_data_manual(ctrl, mode='REPLACE')`
  similarly against `_paste_impl`.
- Do not change any public signature called from `ops.py` or
  `clipboard_feature.py` — `copy`, `cut`, `paste`, `copy_data_manual`,
  `paste_data_manual` must all keep their existing parameter lists.

### Verification
- Repeat the full clipboard smoke test from Phase 2, Step 2.2.
- Additionally test the "manual" pipeline specifically: use the Clipboard

  dropdown) in the N-panel, for both `BONE` and `LAYER` target data types,
